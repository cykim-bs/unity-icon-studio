# 스타일 묶음 작성 가이드

[English](style-packs.en.md)

스타일 묶음(`pack.json`)은 종류별 촬영 구도, 고정 프롬프트 문장, 외곽선, 캔버스 채움, 검사 범위를 담습니다.
기본 묶음은 앱에 들어 있고, 로컬 묶음은 `%USERPROFILE%\.unity-icon-studio\packs\<id>\pack.json`에 두고 `"extends": "default"`로 기본 묶음 위에 덮어씁니다.

## 원본 유지가 기본입니다

아이콘은 촬영본을 **다시 칠한 것**이어야 합니다. 새로 디자인한 것이 아닙니다.

| 바꿔도 되는 것 | 바꾸면 안 되는 것 |
|---|---|
| 재질의 매끈함(클레이·광택 플라스틱), 음영과 빛, 색의 부드러움(조금 밝고 깨끗하게), 모서리를 살짝 둥글게 | 부품의 있고 없음, 개수, 위치, 전체에 대한 상대 크기, 두께, 무늬(격자·창살·줄무늬·판자), 바닥·받침의 모양 |
| 사용자가 첨언으로 직접 요청한 추가(예: 「지붕에 눈」) | 촬영본에 없는 반짝이·별·하트·꽃·잎·소품·엠블럼·글자·효과 |

묶음의 `fidelity`(또는 설정 `generate.fidelity`, 실행마다 고르는 「원본 유지 / 꾸미기」)가 두 방식을 고릅니다.

- **`strict`(원본 유지, 기본):** 위 표의 왼쪽만 바꿉니다. 스타일 참고 그림을 보내지 않습니다(참고 그림의 장식·비율을 따라 그리기 쉽습니다).
- **`stylized`(꾸미기):** 핵심 부품을 키우고, 잔무늬를 줄이고, 작은 반짝이·하트를 더할 수 있습니다. 묶음 `styleRefs`를 함께 보냅니다. 게임 속 모델과 맞아야 하는 아이콘보다는 홍보용 그림에 씁니다.

문장마다 `"when": { "fidelity": "strict" }`처럼 조건을 달아 한 묶음에 두 벌을 둡니다. 조건 키는 `kind`, `refs`, `outline`, `background`, `fidelity`입니다.

## 문장 쓰기

- **잠금(`"locked": true`)** 은 절대 바뀌면 안 되는 문장에 겁니다: 목표(다시 칠하기), 부품 유지 규칙, 구도, 「없는 것을 더하지 않음」, 출력 규격. 첨언은 잠기지 않은 문장만 바꾸거나 문장을 더합니다.
- **유지할 것을 말하고, 개선할 방향은 말하지 않습니다.** 「enlarge」, 「exaggerate」, 「simplify」, 「chibi」, 「charm」, 「sparkle」 같은 말은 촬영본에 없는 변화를 부릅니다.
- **바닥·받침은 촬영본 그대로**라고 씁니다(「keep its base exactly as captured」). 이상적인 바닥을 묘사하면 바닥이 바뀝니다.
- **색은 촬영본에 대해 상대적으로** 씁니다(「a little richer than the capture」). 「deep green」 같은 고정 색은 그림 전체를 다시 칠합니다.
- 참고 그림은 렌더링만 보여 줍니다. 장식이 없는 그림을 고르고, `strict`에서는 쓰지 않습니다.
- 금지어(`bannedTerms`)에는 제품·캐릭터 이름처럼 프롬프트에 나오면 안 되는 말을 넣습니다.

## 첨언으로 요청한 추가

재가공 모델은 첨언이 요청한 추가를 `additions`(짧은 영어 명사구)로 돌려줍니다. 코드는 잠긴 「없는 것을 더하지 않음」 문장 바로 뒤에
「Except what the note asks for: …」 문장을 붙이고, 충실도 검수에 허용 목록으로 넘깁니다. 배경·글자·로고 같은 금지 항목은 이때도 빠집니다.

## 검사·검수·재시도

`strict` 그림은 후처리 뒤 다음을 거칩니다. 한계값은 묶음 `checks.strict`에 있습니다.

| 단계 | 보는 것 | 판정 |
|---|---|---|
| 충실도 측정 | 촬영본과 같은 면적·무게중심으로 맞춘 뒤 행·열 실루엣 폭 차이(`fidelityProfile`), 촬영본 대비 채도·명도 변화(`deltaSaturation`, `deltaValue`) | 범위 밖이면 불합격 |
| | 촬영본 주변에 없던 색 덩어리(`foreignBlobs`), 촬영본 실루엣 밖 조각(`outsideParts`) | 한계 이상이면 「의심」: 검수가 판단, 검수가 없으면 불합격 |
| | 실루엣 일치(IoU) | `iouMin`(기본 0.92) 미만이면 불합격 |
| 충실도 검수(`llm.fidelityReview`: `off`·`claude`·`codex`·`both`) | 촬영본과 생성본을 나란히 보고 추가·크기 변화·빠짐·무늬 변화를 항목마다 `minor`/`major`로 나열 | 코드가 판정: 추가(`major`이거나 2개 이상), 빠짐(`major`이거나 2개 이상), 크기·두께·위치 변화(`major`이거나 3개 이상)면 불합격. 모양 변화와 무늬 변화는 메모 |
| 재시도(`generate.fidelityRetries`, 기본 1) | 지적된 부품만 다루는 교정 문장을 SUBJECT 끝에 붙여 한 장 더 | 그래도 불합격이면 「원본과 다름」으로 표시하고 사람이 고릅니다(그대로 내보내기·꾸미기로 다시·첨언 고쳐 다시) |

- 교정 문장에는 색 이름을 쓰지 않습니다. 색 문제는 「촬영본에 가깝게, 조금만 밝고 깨끗하게」로만 고칩니다.
- `both`면 Claude와 Codex가 각각 검수하고, 하나라도 불합격이면 불합격입니다. Codex는 부품 크기 변화를 더 자세히 짚고, Claude는 더 빠릅니다.
- 재시도는 이미지 한도를 한 장 더 씁니다. 한도·로그인·실행 파일 없음 실패 뒤에는 재시도하지 않습니다.

## 검사 범위 예

```json
{
  "checks": {
    "default": { "size": [0.82, 0.995], "outlineWidthPx": [3.0, 5.0], "saturation": [0.35, 0.62] },
    "prop": { "fill": [0.25, 0.60] },
    "strict": {
      "iouMin": 0.92, "fidelityProfile": 0.012, "foreignBlobs": 2, "outsideParts": 1,
      "deltaSaturation": [-0.05, 0.15], "deltaValue": [-0.08, 0.15]
    }
  }
}
```

`strict`에서는 절대 채도·명도 범위(`saturation`, `value`)를 판정에 쓰지 않고 값만 보여 줍니다. 촬영본 자체의 색이 기준이기 때문입니다.
